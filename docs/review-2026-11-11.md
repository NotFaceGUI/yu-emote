# Review — 2026-11-11

Scope: the new official-shaped `EmoteDevice`/`EmotePlayer` facade, the
`ViewTransform` rotation/composition path, and the CPU/GPU renderers that
consume it.

Baseline checks run with the local `chocola-maid.pure.psb` fixture:

```text
cargo test                                  all green
cargo clippy --all-targets                  no yu-emote warnings (vendor eluna
                                            keeps 6 pre-existing warnings)
cargo fmt -- --check                        clean
psb-player --timeline 待機ループ00 --ticks 10 --out ...   CPU PNG
psb-player --gpu --out ...                  headless wgpu PNG
```

## Correctness issues found and fixed in this pass

| # | Issue | Impact | Fix / evidence | Test |
|---|---|---|---|---|
| 1 | Default player camera double-subtracted the model center | Every facade frame was shifted by `-center * fit_scale`; the old `psb-render` path was centered, the new player was not | `ViewTransform::fit_camera` now returns a pure viewport scale + canvas center; the player transform already subtracts the model center, matching the reference `((p-center)*player_scale rotated + coord) * viewport_scale + canvas_center` | `default_player_camera_centers_the_model`; `psb-player` and `psb-render` are byte-identical at 400x600/tick 0 |
| 2 | `transform_order_mask` position bit was ignored | With the SDK default mask and `scale != 1`, `SetCoord` moved the character by the wrong amount | `EmotePlayer::effective_view` folds `coord *= scale` when `POSITION_TRANSLATE_TO_SCALE` is set, exactly as the reference renderer | `player_coord_honours_transform_order_mask` |
| 3 | CPU rotated clip used the screen-space AABB as the clip | Rotated type-7 clips painted pixels outside the rotated rectangle; GPU was correct | The AABB is now only a work bound. `rasterize_triangle_band`/`rasterize_coverage_band` interpolate the model position and test the model-space `clip_rect`, like the GPU fragment stage | `rotated_clip_uses_model_space_rectangle` (CPU + GPU) |
| 4 | Rotated item extent used only two model corners | Band assignment could cut off the top/bottom of a rotated item | `item_screen_y` transforms all four model AABB corners | covered by rotated render tests |
| 5 | `EmoteDeviceOptions { mask_mode: Stencil }` bypassed `set_mask_mode` validation | The facade could report stencil mode while the renderer used alpha | `EmoteDevice::new`/`headless` now validate and return `UnsupportedFeature` | `unsupported_official_device_calls_are_explicit` |
| 6 | `SetVariable(..., frameCount = 0)` used the timed path | Zero-time writes did not rebuild the scene and control variables could stay pending | `set_variable_timed` routes zero/non-finite frame counts through the immediate `set_variable` | `player_variables_round_trip_by_official_index` |
| 7 | Batch `EMOTE` variables rebuilt the scene once per variable | A BUST/HAIR/PARTS/SMOOTH call paid several 7–8 ms scene rebuilds | `EmotePlayer::set_variables`/`Emote::set_variables` apply all values through `ElunaPlayer::set_variable_immediate` and rebuild once | `batch_variable_writes_rebuild_once`; `psb-render --var` tick-0 hashes differ as expected |
| 8 | `Smoothing` and `MeshDivisionRatio` were listed as supported | The runtime stores them but never consumes them; renderer/plan ignore them | Ledger moved to `StateOnly`; doc comments and `docs/official-api.md` say so | ledger consistency test |

## Open correctness / evidence gaps

| Area | State | Notes |
|---|---|---|
| `SetColor` / `SetGrayscale` | State only | Values are stored/queryable; neither renderer tints pixels. The byte order of the public color argument is also not fully evidenced (runtime treats it as ARGB-like, plan corner colors are `0xRRGGBBAA`). |
| Timed `SetColor` / `SetGrayscale` | Unsupported | Rejected explicitly when `frameCount > 0`; runtime stores a single value only. |
| `SetSmoothing` | State only | No consumer yet; official smoothing semantics not recovered. |
| `SetMeshDivisionRatio` | State only | Tessellation comes from the authored plan/mesh division. |
| Timed `SetCoord` / `SetScale` / `SetRot` | Facade tween | Implemented with the recovered `pow(progress, exponent)` easing, but the native player transition queue and its interaction with `SetQueuing` are not evidenced for these three. |
| `SetQueuing` | Supported for runtime transitions | Does not queue facade-owned coord/scale/rot tweens. |
| `SetMaskRegionClipping(false)` | State only | Alpha coverage is always clipped to the mask region (official default `true`). |
| `SetProtectTranslucentTextureColor` | State only | Stored for diagnostics; blend behavior is fixed by the native blend table. |
| `SetMaxTextureSize` | State only | Stored; actual limits come from wgpu. |
| `SetStereovisionVolume/ParallaxRatio` | Unsupported | Runtime exposes native `stereovision_level`/`stereovision_fov`; the official volume/parallax mapping is not evidenced. Physical stereovision composition is also not implemented. |
| `GetVariable` unknown label | `Option<f32>` | Official returns a float (likely `0`); this API keeps absence explicit. |
| Index enumeration order | Label-sorted | Deterministic, but not authored PSB order. Name-based access is exact. |
| Stencil mask mode | Unsupported | Returns `UnsupportedFeature`; alpha coverage is the implemented path. |
| Pixelate, outer-stencil counting, type-4 particles, type-10 feedback | Outstanding | Renderer work; recorded in the main parity ledger. |
| D3D9 device surface | Not applicable / unsupported | Shader model SM2/SM3, mipmaps, alpha-op selection, `OnDeviceLost`, `OnRenderTarget`. |
| Multi-object `CreatePlayer` overload | Unsupported | One PSB per player. |
| `EmoteFilterTexture` | Not implemented | Loader-side texture filter step; not needed by the current PSB path. |

## Performance and memory risks

Measured/estimated on the 4096² Nekopara fixture. The tick cost
(`eluna` scene rebuild/physics, 7–8 ms) remains the frame ceiling; the items
below are about memory and scaling to several characters.

| Priority | Risk | Why | Recommended change |
|---|---|---|---|
| P0 | Per-player `GpuRenderer` | `EmoteDevice::create_player` creates pipelines, bind-group layouts, sampler, 1×1 white texture and buffers **per character** | Split `GpuRenderer` into a device-shared `GpuContext` (pipelines/layouts/sampler) owned by `EmoteDevice`, plus per-player `GpuSurface` (textures, target, buffers, bind groups) |
| P0 | Duplicate normalized PSB bytes | `Emote::from_bytes` parses/normalizes into `PsbDocument`, then `EmoteRuntime::from_bytes` normalizes again and keeps its own copy and PSB tree. For a 67 MB PSB that is ~134 MB before textures | Add an `EmoteRuntime::from_parsed(psb, normalized_data, options)` constructor and let `Emote` hand its parsed tree over (or drop the document for host players) |
| Mitigated | Decoded textures retained in GPU mode | `EmotePlayer` kept the CPU `DecodedTexture` map (~67 MB at 4096²) alongside the uploaded GPU texture | Added `EmotePlayer::release_decoded_textures()` and `GpuRenderer::render_uploaded`; hosts opt in, CPU rendering then returns `UnsupportedFeature` |
| P1 | `ensure_masks` churn | Mask texture count follows the used group count; an expression can toggle 0↔1↔2 groups and force texture reallocation and bind-group purge every frame | Allocate a stable capacity (or retain a free list) and only recreate when the size exceeds capacity |
| P2 | Per-frame plan/scene allocations | `RenderPlan::from_scene`, `build_scene`, `build_band_plans`, vertex/index buffers and mask buffers allocate every frame | Reuse `Vec`s/arena buffers per player; optionally cache the plan when `is_modified()` is false |
| P2 | CPU mask coverage buffers | One `Vec<f32>` per group per band per frame | Reuse per-thread scratch buffers across frames |
| P3 | `playing_timeline_*` calls | `playing_timeline_info()` allocates a `Vec<(String, u32)>` on every count/label/flags call | Add a cached `playing_timelines()` snapshot refreshed after play/stop/progress |
| Done | Batch variable rebuilds | `set_variable` rebuilt the scene per write | `set_variables` + `Emote::set_variables` now rebuild once |

## Quality notes

- The facade is intentionally broad and forwarding-heavy. Splitting
  `player.rs` into `device.rs` and `player.rs` would improve navigation, but
  the current single file mirrors the official header and is easier to audit
  against it.
- `OFFICIAL_API_SUPPORT` is manually maintained. The test only detects
  duplicates; it cannot prove that every listed method still exists. Keep the
  ledger review as part of interface changes.
- Model-backed tests remain explicit-skip without `YURIS_EMOTE_SAMPLE`
  (`YURIS_REQUIRE_SAMPLES=1` turns a skip into a failure). The GPU tests skip
  when no adapter is available.
- The new rotation/transform code is covered by CPU+GPU parity tests; the
  default-camera and transform-order regressions each have a dedicated test.
- `docs/yuris-host.md` and `docs/official-api.md` now state the `EMOTE`
  `TIME` unit correctly: milliseconds × 0.06 = native 1/60 ticks (the kernel's
  `domain-event-contracts.md` §7.3 still needs the same correction on its
  side).
